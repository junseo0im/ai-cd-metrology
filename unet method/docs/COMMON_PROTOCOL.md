# 세 측정 코드 공통 기준

현재 팀 성능 비교에서는 세 코드 모두 숫자 `3`을 선택해 `sidewall`만 평가한다.
`1=line`, `2=gap` 기능은 코드에 유지하되 이번 비교표에는 섞지 않는다.

| 항목 | 공통 기준 |
|---|---|
| 입력 | 세 방법 모두 동일한 답 표시 없는 원본 PNG |
| 크기 | 임의 resize 금지 |
| 좌표 | 확대된 캡처 픽셀이 아닌 `native` 픽셀 |
| 보정값 | `1 px = 0.1592 µm` |
| 숫자키 | `1=line`, `2=gap`, `3=sidewall`; 복수 선택 가능 |
| sidewall 정의 | 주황/붉은 세로 경계 하나 자체의 왼쪽 edge~오른쪽 edge |
| line 정의 | 인접 sidewall 사이의 교대 구간 중 더 밝은 구간; 서로 마주 보는 edge 사이 |
| gap 정의 | 인접 sidewall 사이의 나머지 교대 구간; 서로 마주 보는 edge 사이 |
| Y 위치 | native 높이의 `20%, 35%, 50%, 65%, 80%` |
| 일반 결과 대상 | 모든 안정 측정 대상을 저장; 최소·중간·최대 대상 선택 금지 |
| 성능 비교 대상 | 화면 중앙의 연속된 5개를 골라 왼쪽부터 `L1-L5`, `G1-G5`, `S1-S5` |
| 정답 | 사람이 육안·장비 자로 측정해 제공한 폭 값; ImageJ 필수 아님 |
| 매칭 | `image_id + 종류 + Y 위치 + target_id`가 같은 값끼리 비교 |
| 반복성 | 동일 위치를 5회 촬영한 측정값의 표준편차 |
| 밝기 | 동일 위치를 어둡게·보통·밝게 촬영해 결과 변화 확인 |
| 속도 | 사진 한 장 전체 처리 시간; 첫 실행은 워밍업으로 제외 |
| 실행 장치 | 서로 다른 노트북의 정확도 시험은 CPU로 통일; 속도 순위는 같은 노트북에서 재실행 |

## Y 좌표 계산

코드는 다음 식을 쓴다.

```text
y_native = round((native_height - 1) × fraction)
fraction = 0.20, 0.35, 0.50, 0.65, 0.80
```

예를 들어 native 높이가 1281이면 약 `256, 448, 640, 832, 1024`행이다.
native 높이가 1246이면 약 `249, 436, 622, 809, 996`행이다. 캡처 이미지가
2배 중복 저장된 경우에는 코어가 중복을 제거한 뒤 native 좌표에서 계산하고,
overlay를 그릴 때만 다시 캡처 좌표로 변환한다.

## CSV 역할 분리

- 팀원: 자신의 코드로 예측 CSV만 생성한다.
- 팀장: 세 예측 CSV와 사람 정답 CSV를 한 번에 `evaluate.py compare`로 비교한다.
- 팀원이 각자 benchmark 전체를 실행할 필요는 없다.
- U-Net은 `unet_inference.py batch` 실행 시 일반 결과와 `unet_predictions.csv`를
  함께 만든다.
- 사람 정답 CSV는 세 팀원의 예측 CSV가 확정된 뒤에만 비교 프로그램에 넣는다.

CSV 열과 결과 파일의 의미는 `CSV_FORMAT.md`를 따른다.
